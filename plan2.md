## Assignment requirements (verbatim)

**Required work:**
- Audit and clean the data
- Create a data dictionary
- Create 3–5 interpreted plots
- Identify data-quality and sampling concerns
- Reserve final test data

**Deliverables:**
1. A 2–3 page data note
2. Preparation code
3. A Streamlit dashboard that reads from Supabase and is deployed on Modal

---

## Key principle

**Reserve the test set before any exploration or cleaning.** Any rule learned from data (imputation values, category mappings, outlier thresholds) must come from the training data only. The test set must never be loaded into the dashboard or used to make cleaning decisions.

---

## Phased plan

### Phase 0: Setup
- Suggested layout: `data/raw/`, `data/processed/`, `src/`, `dashboard/`, `notes/`
- Raw data is never edited in place
- Credentials go in `.env` locally (git-ignored) and in a Modal Secret, never committed
- Keep a decisions log (`notes/decisions.md`): each cleaning choice with a one-line reason

### Phase 1: Reserve the test data
- Record raw row count, column count, and source
- Choose the split method:
  - **Time-based** if there are dates (test = most recent period)
  - **Group-based** if the same entity appears more than once (no entity in both sets)
  - **Stratified** if the target is imbalanced
- Use a fixed random seed; save `test` separately; record the method and sizes

### Phase 2: Audit (training data only)
Record counts for each check:
- Type problems (numbers as text, dates as strings, inconsistent category labels)
- Missingness per column, and whether it looks random or tied to other variables
- Exact and near-duplicate rows
- Impossible or out-of-range values, sentinel codes (e.g. 999, -1)
- Outliers: error or real?
- Leakage: columns unavailable at prediction time or that encode the target

### Phase 3: Clean
- Cleaning lives in `src/prepare.py` as functions (e.g. `load_raw()`, `split()`, `clean()`, `save()`), not loose notebook cells
- Pipeline runs raw → processed with one command
- Fit any learned rules on training data only, then apply the same rules to test
- Add simple validation checks at the end (no duplicate IDs, no nulls in key columns, values in range)

### Phase 4: Data dictionary
One row per cleaned column:

| Column | Type | Description | Units / allowed values | % missing | Cleaning applied | Notes |
|---|---|---|---|---|---|---|

- Type, % missing, and ranges are generated by code
- Description and notes are written by hand
- Save as CSV; include in the data note or its appendix

### Phase 5: Plots (3–5, each interpreted)
Suggested set:
1. Target distribution (balance or skew)
2. Missingness pattern
3. Key feature vs. target
4. Distribution over time or by group (drift or sampling imbalance)
5. Before/after cleaning for one variable

Each plot gets 2–3 sentences: what it shows, why it matters, what is being done about it.

### Phase 6: Data-quality and sampling concerns
Write these as two separate subsections:
- **Quality:** missingness, measurement error, inconsistent coding, outliers, and the action taken for each
- **Sampling:** how the data was collected, under- or over-represented groups, selection or survivorship bias, time period covered, limits on generalization

### Phase 7: Supabase
- Tables for the cleaned training data and the data dictionary
- Test data either kept out of Supabase or in a table the dashboard never queries (say which in the note)
- Row Level Security on; the dashboard uses the anon key with a read-only policy, not the service key

### Phase 8: Streamlit dashboard (`dashboard/app.py`)
- Sections: dataset overview (rows, columns, split sizes), data dictionary table, the 3–5 plots (with filters if useful), data-quality summary
- Reads from Supabase via environment variables or `st.secrets`; queries cached with `@st.cache_data`
- Must run locally before deploying

### Phase 9: Deploy on Modal (`modal_app.py`)
- Image with project requirements plus dashboard files
- Supabase credentials attached as a Modal Secret
- A `@modal.web_server` function that launches `streamlit run` headless on the matching port, bound to `0.0.0.0`
- Test with `modal serve`, then `modal deploy`; confirm the URL works in a private browser window

### Phase 10: Data note (2–3 pages)
1. Data source and scope (~½ page)
2. Test-set reservation: method and sizes (short paragraph)
3. Audit and cleaning: summary table of issue → count → action (~½ page)
4. Key plots with interpretations (~1 page)
5. Data-quality and sampling concerns (~½ page)
6. Links: repo, dashboard URL, data dictionary
